   ```bash
   cd tests/crop-qa
   npm ci
   npx playwright install chromium
   npm test
   ```

## Regressione tremolio Android nella cornice — correzione pubblicata

La segnalazione successiva alla produzione 9026 riguarda **il blog su Android**, anche nella seconda pagina. Nei test con Chromium emulato si è riprodotto il ridimensionamento del frame durante un tocco nella pagina 2 (579 → 1164 px) e durante un drag iniziato rapidamente: le vecchie prove aspettavano invece che il frame fosse già stabile. Con la **sola app corretta e la vecchia cornice** il movimento è ancora riproducibile: per il caso provato servono **entrambe** le modifiche. Il problema completo riferito su Android fisico non è riprodotto né certificato risolto.

- `npm run cornice-interazione`: app simulata e origini diverse; verifica che un resize già in coda sia annullato durante gesto/scroll, che si riprenda con una misura nuova, che messaggi estranei siano ignorati e che il watchdog sblocchi un'interazione interrotta. Nessuna API.
- `tremolio-seconda-pagina.stress.mjs` e `tremolio-android-blog.stress.mjs`: copiano la risposta HTML pubblica del post **solo nel browser di test**, sostituiscono il blocco con la nuova variante e puntano all'anteprima. Le API sono tutte intercettate con dati fittizi. Campionano l'altezza durante un tocco reale emulato e verificano che, dopo il rilascio, la cornice sia sufficientemente alta. Per ripetere: impostare `CROP_QA_BASE_URL` all'anteprima HTTPS, `LF_CORNICE_VARIANT` al percorso assoluto di `cornice-dinamica/CODICE-3-ANTI-TREMOLIO-ANDROID.html` e `LF_ASSERT_STABLE=1`, poi eseguire `npm run tremolio-seconda-pagina` e `npm run tremolio-android`. `LF_HOLD_DELAY=530` verifica la cancellazione di un resize già in coda; `LF_GESTURE_STEPS=165` prova un gesto prolungato.
- `diagnosi-seconda-pagina-blog.mjs`: con le stesse variabili attraversa il percorso completo, scrive nel textarea, cambia modo e dimensione del viewport, crea un esercizio simulato e sposta tessere; `LF_ASSERT_STABLE=1` controlla la stabilità durante la digitazione. Cambiare il viewport in Chromium **non simula fedelmente la tastiera Android reale**.
- `anteprima-blog-simulata.e2e.mjs` (`npm run anteprima-blog-simulata`): verifica la pagina temporanea a due origini con tutte le API sostituite da risultati di esempio. La simulazione non salva dati ma non esegue realmente l'IA né adatta l'esercizio al testo inserito. Il server temporaneo non è il post pubblico né una versione permanente. Un solo item termina con `FINISCO`, non con `AVANTI`.
- `cornice-riordino-desktop.e2e.mjs` (`npm run cornice-riordino-desktop`): prova il drag con mouse a 1440px nella stessa pagina temporanea, su origini HTTPS differenti. Verifica l'immobilità durante il gesto, il posizionamento della parola e il riadattamento finale. Funziona solo mentre il server temporaneo della demo è attivo; API bloccate.
- Usando `LF_WIDTH=320 LF_SCALE=1.6`, i due stress test coprono il font ingrandito. Sul riordino il banco può essere molto più in basso della risposta: la prova riporta prima la tessera in vista, come farebbe l'utente.
- `LF_CORNICE_VARIANT=... npm run cornice-blog` verifica i pulsanti e la ricarica della variante nuova a 320/390/1440px; lo stesso parametro con `npm run riordino-cross-origine` verifica il passaggio da un item lungo a uno breve.

La cornice `CODICE-3-ANTI-TREMOLIO-ANDROID.html` è stata pubblicata nel post dopo conferma dell'utente; `CODICE-3-BLOGGER-ESATTO.html` conserva la versione storica precedente. Non presentare test emulati come prova sul telefono reale. Future modifiche del post richiedono conferma, e future pubblicazioni dell'app richiedono anteprima condivisa e conferma separata.

## Tremolio foto → testo e scorrimento interno dell'iframe

- `tremolio-foto-blog.stress.mjs` riproduce nel blog reale (Pixel 7 emulato) foto → ritaglio → lettura IA → testo caricato. `LF_SCENARIO=idle|swipe` (senza o con dito sullo schermo), `LF_CPU=4` rallenta la CPU, `LF_ASSERT=1` trasforma le soglie in verifiche (iframe che non scorre, nessun salto visibile sopra 120 px), `LF_PHOTO` indica una foto propria (altrimenti ne genera una da 12 megapixel), `LF_OUT` il file JSON.
